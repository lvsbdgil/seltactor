# Реальная обработка фото и видео

## Запуск

Проверено на Python 3.12 и FFmpeg 9.0.2 (требуются исполняемые `ffmpeg` и `ffprobe` в PATH).

```bash
python3.12 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.lock
cp backend/.env.example backend/.env
# Впишите OPENAI_API_KEY в backend/.env локальным редактором.
backend/.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Фронтенд: `npm run dev -- --port 5173 --strictPort`. Vite пересылает `/api` на порт 8000. Документация API доступна на http://127.0.0.1:8000/docs.

Ключ хранится только на сервере в `backend/.env` либо переменной окружения `OPENAI_API_KEY`. Не помещайте ключ в `VITE_*`, исходники, браузер, URL или Git. После изменения `.env` перезапустите backend. `OPENAI_MODEL` настраивает модель; по умолчанию используется `gpt-5.6-terra`, поддерживающая изображения, Responses и structured outputs. Для неё применяется reasoning effort low. Доступность модели зависит от API-аккаунта. Отсутствующий ключ — HTTP 503 с понятной инструкцией; заглушка не подменяет анализ.

## Доступ

Все методы создания и чтения настоящих анализов требуют администраторской сессии. Сначала войдите через интерфейс или `POST /api/auth/login`; см. [AUTH.md](AUTH.md). Подготовленные публичные примеры не вызывают API модели.

## API-контракт

- `GET /api/health` → `{status, configured, model, ffmpeg_available, limits}`. Никаких секретов.
- `POST /api/analyses`: multipart form, повторяемые поля `files`, строки `field`, `crop`, `date` (ISO `YYYY-MM-DD`). HTTP 202 → `{id,status,progress,stage,report,error}`.
- `GET /api/analyses/{id}` → тот же объект; статусы `queued`, `processing`, `completed`, `failed`.
- `report`: `summary`, `observations` (`id,label,severity,description,recommendation,source`), `limitations`, `disclaimer`, `model`, `field`, `crop`, `date`, `images_analyzed`, `files_processed`, `mode:"openai"`.
- `error`: безопасная для пользователя строка либо null.

Процент — завершение этапов локального пайплайна, а не телеметрия внутренней работы OpenAI. Во время вызова модели прогресс остаётся на 60%; модель не предоставляет процент обработки.

## Этапы

1. Приём до 12 файлов. Максимум 50 МБ на фото, 2 ГБ на видео, 4 ГБ на весь набор. Безопасные сгенерированные имена на диске, ограниченные строки контекста, проверка даты.
2. Проверка фото через Pillow по содержимому, а не MIME/расширению. До 60 Мп, корректировка EXIF-ориентации, нормализация прозрачности, JPEG до 1536 px по длинной стороне. Метаданные EXIF не передаются модели.
3. Проверка видео через ffprobe. До двух часов, наличие видеодорожки. Извлечение до шести равномерно выбранных кадров на видео через FFmpeg. Поддержка MP4/MOV зависит от установленного FFmpeg и кодеков. Аудио не передаётся.
4. Общий лимит — 24 изображения на запрос; при нескольких видео бюджет распределяется с резервом для каждого фото. Это выборка, не полный анализ видео. Каждый кадр имеет идентификатор, имя файла и отметку времени.
5. Один серверный вызов официального OpenAI Python SDK: `client.responses.parse`, `input_image` с Base64 JPEG, `text_format=ModelReport` (Pydantic/strict JSON Schema), `store=False`, до 4000 токенов вывода. Таймаут SDK 150 секунд и максимум один повтор. Сжатые изображения отправляются в OpenAI — это оплачиваемый API-запрос при наличии действующего ключа и кредитов.
6. Проверка ответа и ссылок на реально отправленные кадры. Приложение добавляет обязательные ограничения и предупреждение о проверке агрономом. Исходники удаляются из временного каталога после успеха/ошибки. Имена файлов присутствуют в отчёте; отчёты хранятся только в памяти процесса.

Инструкции внутри изображений, имён файлов и пользовательского контекста считаются недоверенными данными. Системный промпт требует визуальных наблюдений и отделения их от гипотез, запрещает придумывать GPS/площади/сектора, утверждать вид или численность вредителя без доказательств, назначать препараты или дозировки.

## Ограничения прототипа

- Нет геопривязки, ортофотоплана, сегментации по секторам, подсчёта насекомых и подтверждённой агрономической точности. Малые насекомые могут быть неразличимы, особенно после уменьшения снимка.
- Нет пользовательской авторизации, постоянной БД и устойчивой распределённой очереди. Это локальный однопроцессный сервер: запускать один uvicorn worker на loopback. Два параллельных анализа, очередь до восьми; максимум 50 сохранённых заданий, срок хранения завершённых отчётов один час. Перезапуск теряет задания и отчёты. При аварийном завершении возможны оставшиеся временные каталоги `seltactor-analysis-*` в системном temp.
- `store=False` отключает сохранение Response как состояния API; это не обещание нулевого хранения провайдером. Политики обработки и возможные abuse monitoring logs определяются OpenAI и настройками проекта.
- Корректный JSON не доказывает правильность вывода. Нужны наземная разметка и испытания с агрономом.
- Реальный ключ подключён. Проверка 2026-11-05 вернула OpenAI HTTP 429 (`credit_balance_exhausted`, `insufficient_quota`): доступный баланс API исчерпан, успешный анализ реальным API пока не подтверждён. Дополнительно проверены подготовка фото/видео и официальный SDK с подменой HTTP-транспорта, включая точный сериализованный запрос и парсинг ответа.

## Проверки

```bash
backend/.venv/bin/python -m pytest backend/tests -q
```

Тесты охватывают отсутствие ключа, загрузку/поллинг/очистку, повреждённые файлы, безопасные ошибки, реальные MP4/FFmpeg кадры, официальный SDK и strict JSON schema без обращения к OpenAI.
