# Доступ посетителей и администраторов

Посетителям доступны заранее подготовленные демоматериалы и демонстрационный отчёт. Загрузка собственных материалов и вызов OpenAI разрешены только после входа администратора. Ограничение проверяется сервером до разбора multipart-загрузки; скрытие кнопок во фронтенде не является защитой API.

## Локальная учётная запись

Для этой установки сгенерирована учётная запись `admin`. Пароль находится только в локальном файле `backend/admin-credentials.txt`, который исключён из Git и доступен владельцу файла (`chmod 600`). Не загружайте этот файл в репозиторий. Доступ к нему через сервер разработки также должен быть запрещён в `server.fs.deny` Vite.

В `backend/.env` хранятся:

- `ADMIN_USERNAME`: логин администратора, по умолчанию `admin`.
- `ADMIN_PASSWORD_HASH`: соль и хеш scrypt; пароля в открытом виде здесь нет.
- `COOKIE_SECURE`: `false` для HTTP на localhost; `true` при переходе на HTTPS.

Существующий `OPENAI_API_KEY` не изменяется при настройке администратора. Для другой установки создайте хеш пароля локально без вывода пароля или ключа:

```bash
backend/.venv/bin/python - <<'PY'
from getpass import getpass
from pathlib import Path
from dotenv import set_key
from backend.auth import hash_password
password = getpass('Новый пароль администратора: ')
if len(password) < 16:
    raise SystemExit('Используйте пароль не короче 16 символов.')
set_key('backend/.env', 'ADMIN_USERNAME', 'admin')
set_key('backend/.env', 'ADMIN_PASSWORD_HASH', hash_password(password))
Path('backend/.env').chmod(0o600)
print('Хеш сохранён. Перезапустите backend.')
PY
```

Этот способ заменяет хеш и не обновляет старый локальный файл с первоначальными данными. После смены пароля старые сессии становятся недействительными. После изменения `.env` перезапустите backend.

## API

- `GET /api/auth/me` → `{is_admin:boolean, username:string|null}`.
- `POST /api/auth/login` с JSON `{username,password}` → тот же объект. Неверные данные: HTTP 401 с общим сообщением. После пяти попыток за десять минут — HTTP 429 с `Retry-After`.
- `POST /api/auth/logout` → `{is_admin:false,username:null}`. Сервер отзывает сессию и удаляет cookie.
- `POST /api/analyses` и `GET /api/analyses/{id}` → HTTP 401 без действующей администраторской сессии.
- Публичный `GET /api/health` включает `is_admin`; наличие ключа (`configured`) не означает доступный баланс OpenAI.

Сессия передаётся cookie `seltactor_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, восемь часов. JavaScript не получает токен и не сохраняет его в `localStorage`. На сервере хранятся только SHA-256-отпечатки случайных токенов, срок действия и имя администратора. Выход отзывает токен. Перезапуск сервера отзывает все сессии.

Изменяющие запросы с браузерным `Origin` разрешены только от `localhost`/`127.0.0.1` на портах 5173 и 8000. Произвольные Origin и `Origin: null` отвергаются. Отсутствие Origin разрешено для CLI-клиентов; авторизация при этом всё равно обязательна. Ответы API помечены `Cache-Control: no-store`.

## Границы локального прототипа

Один администратор и один процесс сервера. Сессии и ограничитель попыток входа находятся в памяти процесса. Для публичного развёртывания нужны HTTPS, корректная настройка `COOKIE_SECURE`, доменные Origin, хранилище пользователей и сессий, общий ограничитель попыток для нескольких процессов. Текущие серверы привязаны к loopback.

Тесты: `backend/.venv/bin/python -m pytest backend/tests -q`. Проверены вход/выход, отозванный, подменённый и просроченный токен, смена хеша, защита API от гостя, чужой Origin, ограничение попыток и прежний медиапайплайн. Запросы OpenAI в тестах подменены, расходов нет.
